# H10.1 — Room Model Correction Pass

Behavioural correction of the watch-together room. No architecture change, no
new provider, no ADR-014 relaxation.

## Corrected room-state model

A room is described by two independent facts.

**Phase** (what the room is doing) — unchanged: `waiting-for-content →
content-selected → countdown → watching → paused → ended/closed`.

**Activity** (whether the room is worth returning to) — new, in
`src/domain/rooms/room-activity.ts`:

| Activity  | Meaning                                                    |
| --------- | ---------------------------------------------------------- |
| `live`    | Someone can walk back into it                               |
| `dormant` | A solo lobby that has gone quiet                            |
| `closed`  | `ended` or `abandoned` — terminal                           |

Dormancy rules (evaluated together, first match wins):

1. `ended` / `abandoned` → `closed`.
2. `active` / `paused` → `live` regardless of idle time.
3. More than one seat taken → `live`.
4. Solo lobby with a selection, idle ≥ 30 min → `dormant`.
5. Solo lobby with no selection, idle ≥ 10 min → `dormant`.

Only `live` rooms are resumable, so dormant rooms no longer appear on the
home rails or offer "continue watching".

## Corrected provider-scope model

`src/domain/watch/room-scope.ts` decides what a room may offer.

- A room created from a service tile is scoped to that service and offers
  exactly one provider. The seventeen-service grid is gone from scoped rooms.
- The room's own shared selection outranks its creation key.
- Catalog keys and watch-registry ids are reconciled in one alias table
  (`prime_video → prime`, `disney_hotstar → hotstar`, `sony_liv → sonyliv`, …),
  so no surface guesses.
- Blocked services (`youtube`) never resolve to a scope, a shelf entry, or a
  room provider list, and the provider row is soft-deleted in the database.

## Stage transition rules

| Condition                                | Stage state |
| ---------------------------------------- | ----------- |
| Selection being written, nothing chosen  | `preparing` (skeleton, never a blank screen) |
| Nothing chosen, host                     | `empty` with "Choose what to watch" |
| Nothing chosen, guest                    | `empty` with a waiting line, no host action |
| Chosen, directly playable                | `embedded` |
| Chosen, anything else                    | `handoff` |
| `handoff` after this person launched it  | `handoff` with "Opened in your browser" and a reopen action |

Choosing a service now writes the selection to the room immediately, so the
stage leaves the empty state at the moment of the external launch rather than
staying blank while the host is in another tab. Embedded playback is still
never claimed for a service StreamFlow may only coordinate around (ADR-014).

## Invite placement

Copy-invite left the top-right utility strip. The invite panel and room key
now sit directly under the stage and selection flow, where the start-of-session
work happens.

## Copy

`home.services.room_name` is now "Watch party on {service}" — context-safe for
every service instead of the static "{service} night".

## Tests

removal, scope derivation and key aliasing, the four stage transitions, and
every dormancy rule. Full product suite: 154 pass.
