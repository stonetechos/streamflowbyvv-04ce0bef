**Certify failure detail (important, and not a product regression).** A fresh `npm run certify` on this
machine failed 12 rows across chromium, firefox and webkit with
`browserType.launch: Executable doesn't exist at /opt/ms-playwright/...`. 60 rows passed, 9 skipped.
The failures are browser binaries missing from the sandbox image, not application defects. However the
harness recorded them as **`fail`**, contradicting the Evidence Guide rule that "a browser that cannot
launch is not evidence"; the correct classification is `blocked`. This is an infrastructure defect
(High, non-critical) and is the single most important finding of this review.

Local evidence is gitignored (`.gitignore:33`), so runs are retained on disk and in CI artifacts, not in
the repository. `RUN-M0R-001` is committed by exception as the M0 remediation baseline.

four registries and six engineering commands exist and are deterministic. Three defects reduce trust

StreamFlow synchronises anything. StreamFlow certifies **zero Tier A and zero Tier B capabilities**;
all 18 providers are Tier C, which is the honest ceiling under ADR-014. One row is unmeasured and two
are blocked. No Certified Threshold exists for any performance metric.

**Remaining blockers.**

1. GATE-01 — missing evidence must fail; today it produces an empty sealed run and exit 0.
2. GATE-03 — environment-caused browser unavailability must record `blocked`, never `fail`.
3. `npm run certify` does not complete in the current environment.

**Current Amber conditions.** Certification 22/25 with 1 unmeasured and 2 blocked · Performance 6/7
baselines and 0/7 thresholds · Capability zero Tier A/B · Debt 9 open with DEBT-005 blocking PROF-08
voice at M3.

**M1 risks.**

- Untrustworthy failure signal until GATE-01/GATE-03 are fixed: a red M1 gate could be an image
  problem and a green one could be an empty run.
- DEBT-003: without thresholds, M1 performance rows can only report baselines, not pass/fail.
- DEBT-013: room capacity is asserted server-side only, directly relevant to the 2–8 participant scope.
- Bun/Node unpinned: CI drift can appear as a product regression mid-milestone.
- Scope pressure toward premium OTT control, which ADR-014 forbids.

## 7. M1 implementation brief (prepared, not implemented)

**User problem.** Two to eight friends in different places want to start the same thing at the same
moment and talk about it, without a fight about who presses play.

**M1 user journeys.** Host creates a private room · host invites by link, code or QR · guest joins,
signing in mid-journey without losing the invite · lobby shows who is here and ready · host starts the
countdown · everyone launches their own provider via deep link and presses play together · voice and
presence run throughout · a member who drifts uses the catch-up assistant · a member leaves and
rejoins · host leaves and the room resolves.

**In-scope capabilities.** Private rooms, 2–8 participants, web desktop first. Preserve as shipped:
authentication, profiles, friends, lobby, waiting room, invites, QR, countdown, presence,
notifications, room lifecycle, provider launcher, branding, design system, realtime.

**Explicitly out of scope.** Premium OTT playback automation · screen capture · accessibility-service
automation · overlay automation · any illegal play/pause/seek control · TV · public event discovery ·
large-room video conferencing · mandatory AI companion · any new provider integration that is not
separately certified. Tier A stays unavailable until a source · adapter · platform · version is

## 8. Final recommendation

The M1 authorization rule requires that `npm run certify` completes with valid evidence and that no
Critical infrastructure defect remains. `npm run certify` exited 1, and two evidence-integrity defects
(GATE-01, GATE-03) mean the certification record can be silently empty or falsely negative. Two
authorization conditions are therefore false.

**Do not authorize M1 — blockers remain.**

Exact blockers:

1. **GATE-01** — `scripts/evidence.mjs` returns success for a run that has no evidence.
2. **GATE-03** — browser-unavailable failures are recorded as `fail` instead of `blocked`, so
   `npm run certify` cannot complete in this environment.

Both are narrow, blocker-scoped fixes permitted under the constitutional limit in I.13, which allows
work scoped to removing a discovered blocker. Once they are fixed and `npm run certify` completes with
a sealed, valid run, this review's remaining conditions are all satisfied and the recommendation
becomes "Authorize M1 Build Mode — human approval still required."
