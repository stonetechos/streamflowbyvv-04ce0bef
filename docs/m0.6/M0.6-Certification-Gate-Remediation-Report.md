# M0.6 — Certification Gate Remediation Report

**Sprint:** M0.6 (blocker removal only)
**Scope:** GATE-01, GATE-02, GATE-03 from `docs/m0.5/M0.5-Human-Gate-Review.md`
**Product code, UI, migrations, schema, providers, capability matrix, performance budget and the
Architecture Constitution were not modified.** No ADR change was required.

## 1. Result-state vocabulary

`scripts/lib/result-state.mjs` is now the single authoritative definition of the legal result states
(`pass`, `fail`, `blocked`, `unmeasured`, `unknown`, `not_applicable`) and of the run sealing state
machine:

```text
RUNNING
  -> PASSED
  -> FAILED
  -> BLOCKED
  -> UNMEASURED
  -> CANCELLED
```

Only `PASSED` plus a valid completion marker constitutes a successful run. `blocked` is never
converted to `pass`, `fail` is never converted to `blocked` outside the explicit environment
signatures listed below, and `unmeasured` is never converted to `pass`.

## 2. GATE-01 — missing evidence must not seal success

| Rule                                          | Implementation                                                                 |
| --------------------------------------------- | ------------------------------------------------------------------------------ |
| Mandatory evidence defined in one place       | `docs/registry/required-evidence.json` (24 entries, exact and prefix matching) |
| Validated before sealing                      | `scripts/evidence.mjs` step 2, after schema validation                         |
| Missing evidence sets a non-success run state | `BLOCKED` (missing) / `FAILED` (schema)                                        |
| Missing identifiers recorded                  | `summary.missingEvidence`                                                      |
| Refusing stage recorded                       | `summary.refusedAtStage`                                                       |
| Partial summary written                       | `summary.json` with `sealed: false`, `complete: false`                         |
| Non-success index written                     | `index.json` with `complete: false` and the run state                          |
| No completion marker                          | `completed.json` is never written and is removed if stale                      |
| Not sealed, no release recommendation         | Pipeline halts before `report-release.mjs`                                     |
| Dashboards cannot read it as successful       | `latestSealedRun()` requires `sealed && completed.json.complete === true`      |
| Zero records is never successful              | Explicit check in `scripts/evidence.mjs`                                       |
| Non-existent run is never successful          | Refuses with exit 1 and creates no directory                                   |
| `CERT_FORCE_RUN=1` cannot bypass validation   | Force is applied only after schema and mandatory validation both pass          |

`scripts/report-release.mjs` and `scripts/milestone.mjs` were switched from `latestRun()` to
`latestSealedRun()` so an unsealed or refused run can never drive a recommendation or a gate status.

## 3. GATE-02 — sealed runs are still validated

Schema validation (`schemaViolations`) now runs unconditionally, before the sealed-run short circuit.
A malformed record introduced into an already sealed run revokes the seal, writes a partial summary
with `refusedAtStage: schema-validation` and exits non-zero. Illegal result states are rejected in the
same pass.

## 4. GATE-03 — environment failures classify as blocked

`classifyStageFailure()` inspects a failing stage's combined output and returns `blocked` only for
recognised environment signatures (browser executable absent, `playwright install` prompts, missing
host dependencies or shared libraries, absent `$DISPLAY`, missing module, missing credential, or a
downstream evidence refusal whose own run state is `BLOCKED`). Every other non-zero exit remains
`fail`, so a genuine assertion failure can never be downgraded. Stage output is captured to
`<run>/logs/<stage>.log` as evidence of the classification.

The pipeline no longer halts on a blocked stage — downstream evidence validation decides honestly —
except for evidence collection itself, which halts so an unsealed run never reaches the release
recommendation. `scripts/certify.mjs` records `runState` and exits `0` passed, `1` failed, `2`
blocked.

## 5. Fixtures and self-test

`scripts/check-gates.mjs` (`npm run gates:check`, also wired into `npm run verify` and the
`certification-guard` workflow) exercises all three gates against isolated fixtures in
`tests/certification/fixtures/gates/`:

```text
PASS  GATE-01 non-existent run refuses
PASS  GATE-01 non-existent run creates nothing
PASS  GATE-01 empty run refuses
PASS  GATE-01 empty run not sealed
PASS  GATE-01 empty run has no completion marker
PASS  GATE-01 missing mandatory refuses
PASS  GATE-01 missing identifiers recorded
PASS  GATE-01 refusing stage recorded
PASS  GATE-01 index marked non-success
PASS  GATE-01 CERT_FORCE_RUN cannot force a pass
PASS  GATE-02 sealed run still validated
PASS  GATE-02 seal revoked on malformed record
PASS  GATE-03 missing browser is blocked
PASS  GATE-03 assertion failure stays fail
PASS  GATE-03 clean stage is not downgraded
```

Fixtures are staged into and removed from the evidence root by the self-test; no historical run is
created, mutated or pruned. `RUN-M0R-001` was left byte-identical apart from a restored
`completed.json` marker, which records the state it already had.

- Bun and Node version pinning in CI, the four missing intentional-failure product fixtures, and
  DEBT-003 certified thresholds remain open M0.5 observations, outside this sprint's scope.

decide on M1 authorisation; this sprint does not grant it.
