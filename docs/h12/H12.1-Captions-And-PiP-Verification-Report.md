# H12.1 — Caption and Picture-in-Picture Capability Verification Report

Sprint: H12.1 (follow-up to H12)
Date: 2026-08-09
Scope: verification only. The theatre box player was **not** redesigned or rewritten.
Environment: Chromium (Playwright, headless), local dev server, viewport 1280x900.

## 1. What was verified

Two gaps left open by the H12 report:

1. Captions were only verified as *correctly hidden* against a 0-track source.
2. The unsupported-Picture-in-Picture branches could not be reached, because the
   sandbox browser supports Document PiP.

Both are now exercised against the shipped player.

## 3. Caption verification — PASS

Fixture: 30s VP9/Opus clip with two sidecar WebVTT tracks (English, Hindi),
four cues each, deliberate gap between 18s and 20s.

| Case | Observed | Verdict |
| --- | --- | --- |
| Control appears only when tracks exist | control present; options `Off / English / हिन्दी` | PASS |
| No-track source | caption control absent, `textTracks.length === 0` | PASS |
| Enable English | `showing = en`, active cue "English caption one at one second." at t=3.10s | PASS |
| Switch language to Hindi | `showing = hi`, active cue "हिन्दी कैप्शन एक…" at t=4.44s, exactly one showing track | PASS |
| Sync after seek to 13s | active cue "हिन्दी कैप्शन तीन, बारह सेकंड पर।" at t=14.39s | PASS |
| Fullscreen | same cue still showing at t=15.33s | PASS |
| Document PiP | `showing = hi`, cue three rendered in the floating window at t=17.74s | PASS |
| After PiP exit | `showing = hi` retained, no active cue at t=19.08s — correct, that timestamp falls in the authored 18s–20s gap | PASS |
| Disable captions | `showing = null`, no active cues, tracks still discoverable | PASS |
| Console | no errors across the whole run | PASS |

Selection survives every mode change: it is stored against a stable track id
(`track.id`, falling back to positional `track-N`) rather than an object identity
that a remount would break.

## 4. Picture-in-Picture branch verification — PASS

Driven with a deterministic capability override so each branch is reached on a
browser that natively supports all of them.

### (a) Document PiP supported
- Floating window opened: 1
- Custom in-window controls rendered: yes (`[data-sf-player-controls="pip"]`)
- Main document held 0 `<video>` elements while floating, stage placeholder shown
- On exit: exactly 1 `<video>` back in the stage slot, playing, t=1.13s -> 4.10s with no restart

### (b) Only element PiP supported
- Control reports `data-sf-pip-support="element"`
- Honest note shown: "This browser floats the video with its own controls. Full controls stay here in the theatre."
- Request succeeded: `document.pictureInPictureElement` set, native browser controls used
- No custom floating window was opened (correct — 0 extra windows)
- Element stays in the stage DOM throughout; still exactly 1 `<video>`
- Playback continuous: 0.93s -> 2.77s -> 3.79s across enter and exit, never restarted

### (c) No PiP support
- Control is `disabled`, reports `data-sf-pip-support="none"`
- Message shown: "This browser can't float the player. Everything still works in the theatre."
- Forced click changed nothing: 0 floating windows, no `pictureInPictureElement`
- Playback unaffected and continuous (0.94s -> 2.16s)

## 5. Regression protection

`tests/product/h12-theater-box.test.ts` now covers:
- caption reading: empty source, kind filtering (`descriptions`/`chapters`/`metadata` excluded), label fallback to language then position, stable positional ids
- PiP branching: document preferred over element, element fallback, `none` when neither exists, SSR safety, and the override seam including its restoration to real detection

202 product tests pass.

## 6. Explicitly not verified

- **Embedded/burned-in captions inside the media container.** Only sidecar WebVTT
  tracks were exercised. In-container tracks depend on the source and codec.
- **Caption styling/positioning fidelity.** Cue text and timing were asserted
  programmatically; visual rendering was captured in screenshots but not
  pixel-compared.
- **Real browsers lacking PiP.** Branch (c) was reached via the override, not on a
  genuinely PiP-less engine. The branch logic is proven; the specific behaviour of
  an unknown browser is not.
- **OTT provider playback and captions.** Out of scope and not possible:
  launch-only per ADR-014. No provider caption track is read, controlled, or
  displayed by StreamFlow.
