## Open Row Review

### CERT-EXP-01 — WCAG 2.1 AA on all launch surfaces

- **Why open:** WP10 extended the automated sweep to all thirteen launch surfaces, but recorded the row **Unmeasured**, not pass, because an automated sweep detects only a minority of AA failures. This is stated by PROF-09's own `limitations` field and required by `K-launch-certification.md`.
- **Product implementation sufficient?** Yes, as far as the repository can show — no accessibility defect is cited as the blocker; the blocker is measurement method.
- **Manual audit required?** **Yes.** This is conflict C-3 and it is the sole reason the row is open.
- **Fault-injection profile required?** No. **Three-engine environment required?** No — the row's platform is `web-desktop`; PROF-09 supports `web-chromium` only. **External dependency?** A human auditor.
- **Exact prerequisite:** a named manual-audit owner plus an authorized record format capturing auditor, date, environment, steps, observations and result. **Already available?** No — no manual-audit record schema exists in `docs/certification/`.

### CERT-PROV-02 — One-step fallback, announced, reversible

## Execution Phases

Planned only. Nothing below was executed.

### Phase 0 — Retention and prerequisite resolution
- Establish, under governance authorization, where new evidence is retained and whether the ignored path is corrected or an approved alternative destination is named (RET-1 / DEST-1).
- Establish source-revision binding: the run must be executed at a clean tree and the recorded `COMMIT` must match the reviewed revision (REV-1).
- Establish RUN-ID uniqueness: no reuse of an existing ID; `CERT_FORCE_RUN` must remain unset.
- Confirm profile availability (PROF-01/04/05/07/09) and identity provisioning (ID-1).
- Confirm the browser environment actually launches for every engine intended in the seal (BR-1).
- Confirm governance prerequisites C-2/GOV-1 and the PROF-09 manual-audit owner.
- **Exit condition:** every Gate A item below is satisfied. No later phase may start otherwise.

### Phase 1 — Automated certification
- Execute only rows marked *Ready to execute*: ROOM-01/02/03/04, PRES-01/02, WP-01/02, PROV-01, EXP-02 — plus SYNC-C-01 once BR-1 clears.
- Capture raw Playwright output, the JSON report, per-row records, and full failure detail for any non-pass.
- Claim nothing until Phase 4 completes. A green console is not certification.

### Phase 2 — Manual certification
- Perform only the authorized PROF-09 manual accessibility audit for CERT-EXP-01.
- Record auditor identity, date, environment, exact steps, observations and result.
- An automated sweep may not be substituted for the manual record; a passing sweep alone leaves the row Unmeasured.

### Phase 3 — Provider and sync fault testing
- Execute only if the fault-injection profile and seam for CERT-PROV-02, and the web-mobile environment for CERT-SYNC-C-02, are already authorized and available.
- Neither exists today. No seam is created by this plan and no unavailable profile is bypassed.
- If still unavailable, both rows remain `blocked` with the named blocker recorded honestly.

### Phase 4 — Evidence verification
- Verify: RUN-ID uniqueness and format; recorded commit equals the reviewed revision; every record maps to a registry row; record count completeness against `required-evidence.json`; implementation-report-to-run mapping; retention (the artifacts exist after a fresh checkout) and immutability.
- Any verification failure invalidates the run for release purposes.

### Phase 5 — Three-engine certification seal
- Runs only after Phases 0–4 complete.
- Uses exactly the engines and profiles the authorities require; per-row three-engine coverage beyond row platform is *Recommended, not a certification requirement*.
- Partial or incomplete evidence is never sealed. Note the structural fact: while `CERT-PROV-02`, `CERT-SYNC-C-02`, `CERT-VOICE-01/02` remain blocked, `scripts/check-gates.mjs` will refuse the seal. Resolving that is a governance decision, not an execution decision.

### Phase 6 — M1 release review
- Begins only when evidence is complete and traceable.
- Confirms no row was improperly promoted and no provider, sync, room or accessibility overclaim remains.
