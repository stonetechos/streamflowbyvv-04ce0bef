## 3. Product behavior implemented

**Defect found (real, reproduced twice in a browser).** A guest opening an invite link to a full room was shown the generic fallback _"We couldn't find that room / No open room matches that code."_ The domain had correctly raised `SF-ROOM-CAPACITY-EXCEEDED`; the refusal was then erased in the UI state before it could be read.

Cause: `useHome` held the refusal of the action the person had just taken and the failure of the background Home snapshot re-read in **one** state slot. A snapshot that resolved successfully a moment later cleared the refusal, and `refusalMessageKey` fell back to `home.join.not_found`.

Fix (presentation only, no rule moved): the hook now keeps `actionError` and `snapshotError` separately and exposes `actionError ?? snapshotError` under the same public `error` field. No signature, no service, no domain rule changed; capacity remains `RoomFlowService`/`RoomService`'s decision (ADR-013).

Observed after the fix: **"Room is full. This room is full."** (`error.room.capacity_exceeded` + `.title`), reference code `SF-ROOM-JOIN`, and the lobby still holds 2/2 seats.
