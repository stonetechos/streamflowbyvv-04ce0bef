## 2. What was implemented

WP1 could only park both rows as `unmeasured`: countdown zero was not observable
from outside the app, and `room_state` carries no stage column.

- `src/features/waiting-room/use-room-countdown.ts` — the hook now records
  `reachedZeroAt`, the instant _this_ client observed the shared, server-written
  countdown target pass. It is an observation only; nothing branches on it.
- The same effect now also arms one timer for the known target instant instead of
  relying solely on the 250 ms display grid. This changes _when a client notices_
  zero, never _who decides_ it.
- `src/shared/constants/system-constants.ts` — added
  `COUNTDOWN_RUNTIME.ZERO_SETTLE_MS` (10 ms), an operational settle for that timer.
- `src/features/waiting-room/components/waiting-room.tsx` — exposes
  `data-sf-countdown-zero-at` alongside the existing `data-sf-stage`.
- `tests/certification/watch-party/m1-watch-party.spec.ts` — rewritten to drive
  three real signed-in browsers, wait until all are in the lobby, have the host
  arm the countdown through the Data API under its own RLS privileges, then
  measure zero spread and stage parity from the DOM.
