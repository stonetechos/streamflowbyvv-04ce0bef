| **Release status** | **Blocked.** `scripts/evidence.mjs` plus `docs/registry/required-evidence.json` v1.1.0 make all 14 M1 identifiers mandatory for a seal; no run in the tree satisfies that, so no successful run exists and no release review can be grounded. |

**Single dominant root cause (High confidence):** `.gitignore` contains the line `tests/certification/evidence/`. The evidence directory is git-ignored wholesale. `RUN-M0R-001` survives only because it was force-added and is tracked (`git ls-files tests/certification/evidence` returns 25 record files, all under `RUN-M0R-001`). Every M1 run was written to an ignored path, was therefore never committed, and did not survive into this revision. This is a retention/commit defect, not a certification-semantics defect and not evidence of overclaim.

This finding **extends and worsens** Finding R1 of `docs/m1/M1.13-Final-Certification-Readiness-Review.md`. M1.13 (reviewed tree `be5c440`) observed three runs present: `RUN-M0R-001`, `RUN-M1WP9-001`, `RUN-M1WP10-001`. At `f1ae897` only `RUN-M0R-001` remains. 7. Read `.gitignore` and the commit log to establish the retention mechanism.
8. Where repository truth could not distinguish causes, recorded **Unknown**.
