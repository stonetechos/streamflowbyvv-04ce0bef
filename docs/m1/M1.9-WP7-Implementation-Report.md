## 2. Finding

Measuring the row honestly exposed a false-sync surface. A provider catalog row
that stores `play_pause: supported` was translated straight into
`syncMode: "controlled"` and then into launch class `supported`, so the lobby
announced a controlled playback surface for a provider that holds **no**
capability certification. Repository truth is that the certification registry is
empty and every capability resolves to Tier C (PROV-A1, ADR-014). The UI claim
and the evidence disagreed; the run recorded `fail`.

## 3. Change made

`src/domain/providers/provider-launch-coordinator.ts`

- `classify()` now takes the launch platform and, before announcing `supported`,
  asks `resolveCapabilityTier()` whether a Tier A certification exists for the
  capability tuple. With the registry empty this is always false, so a
  control-claiming catalog row is presented as `manual_sync` — coordinated manual
  sync, the honest Tier C class. A certified tuple would still be allowed to
  present `supported`; nothing is hard-coded to a provider name.
- `requiresManualPlay` remains unconditionally `true`; no transport, scrubber, or
  play/pause affordance exists anywhere on the room surface.

`src/features/waiting-room/components/provider-launch-panel.tsx`

- Instrumentation only: `data-sf-launch-panel`, `data-sf-launch-class`,
  `data-sf-launch-status`, `data-sf-launch-manual`, `data-sf-launch-target`,
  `data-sf-launch-primary`. No behaviour change.

`tests/certification/sync/m1-sync-tier-c.spec.ts`

- `CERT-SYNC-C-01` now drives a real host journey: provision identity, create the
  room, open the lobby, expand Room details, select a provider through the
  radiogroup, then intercept `window.open` to capture the hand-off without
  navigating to a third party. It asserts exactly one external hand-off, manual
  play required, and the absence of every forbidden affordance.
