# M1.17 — RET-1 Resolution Report

Mode: BUILD MODE, retention infrastructure only. No certification executed, no evidence
generated, no row promoted, no run sealed.

## 1. RET-1 implementation summary

RET-1 (M1.16 §Blockers) is that certification evidence was written to
`tests/certification/evidence/`, a path excluded by `.gitignore:33`, so no run survived the
process that produced it (M1.14 RC-1, M1.15). Four changes resolve it for **future** runs:

1. the ignore rule is narrowed so evidence is version-controlled, with only bulk runner
   output (`videos/`, `artifacts/`) still ignored;
2. a manifest module binds each run to an exact 40-character source revision, its work
   package, owning engines, mapped certification rows and every retained artifact's digest;
3. `scripts/evidence.mjs` fails closed on any missing element of that contract and writes the
   completion marker strictly last;
4. `scripts/check-retention.mjs` proves the contract on throwaway fixtures, wired into
   `npm run verify` and the existing certification-guard workflow.

## 2. Authority and scope review

No authority conflict was found that blocks RET-1. The Evidence Guide already requires run
identity `(runId, commit, environmentProfile, region)`, immutability of a sealed run, and
mandatory-evidence validation; `.gitignore` silently defeated all three. Repairing the
destination restores the frozen contract rather than creating a new governance rule. No
certification row, threshold, state vocabulary, profile, ADR, Launch Envelope or Constitution
text was touched. `src/` is untouched.

Conflict RET-1 (M1.15) — "Evidence Guide mandates durability but `.gitignore` prevents it" —
is resolved in favour of the higher authority (Evidence Guide) by changing the lower-authority
repository configuration.

## 8. RUN-ID durability verification

RUN-ID semantics from `run-context.ts` / `certify.mjs` are unchanged. Verified: identity is
now present in `manifest.json`, `index.json`, `summary.json` and `completed.json`; a second
run writes a separate directory and does not mutate the first (self-test R1); a sealed and
valid run is preserved byte-for-byte unless `CERT_FORCE_RUN=1`, which still cannot bypass
validation. Uniqueness remains derived from `(timestamp-to-the-minute, short SHA)` or an
explicit `CERT_RUN_ID`; no rename or fabrication of historical runs occurred.

Backward compatibility: runs sealed before this contract (`RUN-M0R-001`) have no manifest and
are explicitly preserved unchanged; the tool reports the absence rather than rewriting them.

## 9. Source-revision binding verification

`resolveSourceRevision()` captures `git rev-parse HEAD` (or a pinned `CERT_COMMIT_SHA`) and
requires a full 40-hex object name. A branch name, tag, `latest` or human version is rejected
and refuses the seal (self-test R8). The SHA is stored in the manifest, index, summary and
completion marker. Dirty-tree policy is **not defined by any frozen authority**: the flag is
recorded as `sourceRevision.workingTreeDirty` and does not by itself refuse a seal. That policy
remains unresolved and is left to governance.

## 10. Evidence manifest and index verification

The manifest lists RUN-ID, work package, engines, rows with owning engine and status, revision,
environment profile, region, run state, counts, retention descriptor and every retained artifact
with size and SHA-256. Sealing recomputes each digest: a missing or altered artifact refuses the
seal (self-test R6, R10). The index carries RUN-ID, revision, work package, engines, destination
and the record set; refused runs write `complete: false` and no marker. No entry was added for
missing historical M1 evidence.

## 11. Completion/sealing behaviour verification

Order enforced: schema → mandatory evidence → retention → manifest → index → summary →
completion marker last. Missing manifest input, missing revision, missing row-to-engine mapping,
missing work package, missing artifact or an ignored destination each refuse the seal, remove any
marker and exit non-zero.

## 14. Retention model classification

**Repository-retained.** Destination `tests/certification/evidence/<RUN-ID>/`; owner is version
control; review path is `manifest.json` then `summary.json`; binding is a full commit SHA; failure
behaviour is fail-closed refusal with a visibly incomplete run; discovery is by RUN-ID, work
package, row, engine, revision or result state from the manifest. Release review can locate any
future run from the repository alone. Described as **repository-retained and revision-traceable**,
not cryptographically immutable.
