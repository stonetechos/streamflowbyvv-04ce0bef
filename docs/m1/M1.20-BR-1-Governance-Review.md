# M1.20 BR-1 Governance Review

## Executive Summary

This is a read-only review of BR-1 — the three-engine browser environment prerequisite identified by M1.19 as the first unresolved blocker after RET-1 (M1.17) and DEST-1 (M1.18).

Three findings determine the outcome.

1. **The version mismatch reported by M1.19 is reproducible from read-only repository and image metadata alone.** `playwright-core@1.62.1`'s own `browsers.json` declares the required builds (`chromium` rev 1234, `firefox` rev 1538, `webkit` rev 2336); the browser cache at `/opt/ms-playwright` contains `chromium-1194`, `firefox-1495`, `webkit-2215`. No browser was launched, installed, or downloaded to establish this; the comparison is metadata-to-directory-listing.
2. **The cause is an incompatible environment image, not a repository defect.** `package.json`, `bun.lock`, `playwright.config.ts` and the CI workflow are internally consistent. The browser cache belongs to an older Playwright release line than the pinned one. Nothing in the repository can be edited to make revision 1194 satisfy a package that resolves revision 1234.
3. **Engine scope is not defined by the frozen authorities.** No document in `docs/blueprint/` — Constitution, Launch Envelope, K-launch-certification, ADR-014, PROV-A1 rows — names Chromium, Firefox or WebKit, or states how many engines a seal requires. The only "three-engine" statements are (a) three Playwright projects in `playwright.config.ts` and (b) M1.13's release-review expectation. M1.16 already recorded that no Constitution clause mandates three engines. That gap is a genuine governance ambiguity, not something this review may fill.

Consequently the final decision is **C**: BR-1 requires external governance **and** environment provisioning before certification may proceed.

Explicit statements of non-action:

- **No browser binaries were installed.**
- **No Playwright version changed.**
- **No environment was provisioned.**
- **No certification executed.**
- **No evidence generated.**
- **No RUN-ID created.**
- **No certification state changed.**

The only file created by this sprint is this report.

## Browser Environment Review

The failure mode is precisely locatable without launching anything.

`playwright-core@1.62.1` ships `node_modules/playwright-core/browsers.json`, which is the authoritative statement of which browser build that package will resolve:

| Browser                 | Required revision | Required browser version | Expected cache directory       |
| ----------------------- | ----------------- | ------------------------ | ------------------------------ |
| chromium                | 1234              | 151.0.7922.34            | `chromium-1234`                |
| chromium-headless-shell | 1234              | 151.0.7922.34            | `chromium_headless_shell-1234` |
| firefox                 | 1538              | 153.0                    | `firefox-1538`                 |
| webkit                  | 2336              | 26.5                     | `webkit-2336`                  |
| ffmpeg                  | 1011              | —                        | `ffmpeg-1011`                  |

The cache at `PLAYWRIGHT_BROWSERS_PATH=/opt/ms-playwright` contains: `chromium-1194`, `chromium_headless_shell-1194`, `ffmpeg-1011`, `firefox-1495`, `webkit-2215`, `webkit_ubuntu20.04_x64_special-2092`.

Every browser directory the pinned package expects is absent; every browser directory present belongs to a different, older revision line. Only `ffmpeg-1011` matches. This reconciliation is derived entirely from a JSON file inside the installed package and a directory listing — it required no launch, no install, and no network access, and it independently reproduces the error paths M1.19 reported (`chromium-1234`, `chromium_headless_shell-1234`, `firefox-1538`, `webkit-2336`).

### Repository concern or external concern

**External environment concern, with one narrow repository-adjacent aspect.**

- The mismatch itself is external: the repository pins `1.62.1` consistently and declares no image; the incompatible cache is supplied by the execution image, which no repository file defines.
- The repository-adjacent aspect is that `.github/workflows/playwright.yml:21` installs Chromium only. Aligning that with a three-engine seal would be a repository change — but it is not authorized here, and it cannot be made without first settling the engine-scope question, since installing three engines silently asserts a three-engine answer.

## Final Decision

**C. BR-1 requires external governance and/or environment provisioning before certification may proceed.**

This decision follows because every condition for C is met and the conditions for A and B are not:

- **Engine scope is ambiguous.** No frozen authority names a browser engine or an engine count; M1.13 and M1.16 conflict (BR-1-A), and configuration conflicts with CI (BR-1-B).
- **Engine deviation is not authorized.** No exception path exists, and no authority names who could grant one.
- **Environment provisioning is unavailable within this sprint and within the repository.** The required builds are absent from an image the repository does not define, and provisioning is prohibited here regardless.
- **Required facts remain unresolved:** the OS of the execution image, the OS-dependency status of every engine, and the browser product versions of the installed builds.

Decision A is refused because the authorities do not define acceptable engine scope. Decision B is refused because engine scope is _not_ unambiguous — provisioning alone would not tell anyone how many engines a valid seal needs, and choosing quietly would be exactly the "practical workaround treated as an approved certification decision" that this sprint forbids. The existence of a technically possible workaround — a `CERT_CHROMIUM_PATH` override, or a Chromium-only seal — does not make BR-1 resolvable, because neither is an approved certification decision.

Restating the sprint's required assertions: **no implementation changed; no browser binaries were installed; no Playwright version changed; no environment was provisioned; no certification executed; no evidence generated; no RUN-ID created; no certification state changed.** Exactly one file — this report — was created.
